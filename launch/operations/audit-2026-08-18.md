## What was genuinely broken

### P1 — eBay could present USD / non-UK offers *(FIXED, deployed, verified live)*

Joe reported eBay offers opening USD-priced comics. Three independent faults:

1. **A UK/US region toggle** on `/search` and in the navbar. Choosing US — or
   any stale `?region=us` URL — selected the `EBAY_US` marketplace, so a UK
   shopper saw US inventory priced in dollars presented as Catch Comics offers.
2. **No location filter on the Browse query.** Even on `EBAY_GB`, results
   include overseas sellers who merely ship to the UK. A live probe of
   "Absolute Batman" returned a **JP-located item**.
3. **`currency || 'GBP'`** asserted GBP for anything eBay left unlabelled — the
   one route by which a non-GBP amount could reach a customer wearing a £ sign.

**Best-price was contaminated as well.** Sorting is on `price.value` as a bare
number, so a USD 8.99 listing outranked a GBP 10.99 one and became the
"From £X" hint on search cards.

Fixed at the query boundary in `lib/ebay.ts`, which covers all four call sites
at once (product offers, price hints, `/api/prices`, search) rather than four
scattered patches. Anything not provably GBP is dropped rather than guessed.

Also removed the `ebay.com → ebay.co.uk` host rewrite in `wrapEpn`. It made a US
listing *look* like a UK one while still sending the customer to overseas stock
— disguise, not a fix.

The region selector was **removed rather than left inert**: the navbar now
states "United Kingdom" as a fact instead of offering a choice that must not be
taken.

### P2 — the Command Centre was showing June *(FIXED)*

Joe opened the Command Centre and could not find Browser Trust. The integration
was never missing. Two entry points both called themselves "Command Centre":

- `launch/open-dashboard.bat` printed *"Generating Catch Comics Founder Command
  Centre"* and opened `launch/dashboard.html`
- that page is generated from `LAUNCH.md`/`WEEK.md`, frozen since 2026-06-23

So it rendered the June sprint — "Data is 47 days old", "Launch July 1, 2026",
Smoke Test V3, a 36% readiness bar — and no Browser Trust card, because it
predates it. Every symptom is explained by that one page.

Ruled out first, with evidence: `main` contains the card; the bridge exists and
listens on 8319; `/status` and `/run` respond; the 8317 server was already
serving the correct checkout. Not a stale server, stale JSON path, cache, or
render error.

`open-dashboard.bat` now opens Mission Control. The sprint dashboard is
preserved as history but banner-marked, so it cannot pose as current status.

## The fuse — the finding that matters most

**Catch Comics is roughly three weeks from having almost no stored prices.**

Nothing has refreshed since **2026-08-09**. The retailer syncs are deliberately
disabled — correctly, they caused the Inngest execution incident — and
`cleanup-stale` soft-deletes anything unseen for 30 days. So today's visible
prices expire on a rolling basis:

- oldest visible listing last seen **2026-07-18** → expiring **now**
- newest visible listing last seen **2026-08-09** → expires **~2026-09-08**

This is invisible in a single-day snapshot, which is why `npm run
retailer:freshness` now measures the expiry curve and not just a total.

The containment is right. The consequence is that the shelf empties unless a
refresh path exists. **World of Books carries 48,581 of the 48,632 priced
products and is `scheduled_sync_disabled = true`, with no gated CLI refresh
path** (it is Shopify, not AWIN).

## Comparison depth — the honest numbers

Joe's instinct that "too many comics have only eBay pricing" is correct, but the
cause is the opposite of what it looks like.

| Measure | Count |
|---|---|
| Catalogue | 150,663 |
| Products with any priced offer | 48,632 (32%) |
| …with **exactly one** retailer | 48,631 |
| …with **2+** non-eBay retailers | **1** |
| …with 3+ | **0** |
| Stored eBay-only products | 0 |

**There is effectively no multi-retailer comparison anywhere in the catalogue.**
One product has two or more genuine retailers.

**eBay contributes zero stored rows.** It is a live Browse API lookup performed
at request time, so it appears on every product page while the database shows
none. That gap is exactly why the site *feels* eBay-only while the data says
otherwise: the stored retailers have aged out, leaving live eBay as the only
thing consistently present.

stub rows that are correctly excluded from coverage.

The core rule holds: none of this should be solved by loosening identity
matching. One trustworthy retailer beats three wrong matches.

## Cost and automation safety

- **Cost Guard: GREEN** (source: production).
- Containment intact: World of Books, Amazon UK, Lets Buy Books and Scholastic
  all carry `scheduled_sync_disabled = true`.
- Nothing was resumed. No paused Inngest function was restarted "to see what
  happens", and no historical events were replayed.
- Audit cost was effectively zero: 6 eBay Browse calls total (4 probe + 2
  verification), DB aggregates only with no row dumps, and no bulk operations.

**Resumption is not currently justified.** The retailer sync remains paused
because the criterion "current data sources can actually complete successfully"
is unproven for World of Books — the 25,000-product Shopify `products.json`
page cap makes a full 190k refresh impossible by that route, which is the
original reason the sync never completed and the queue re-enqueued forever.
